# Книга рецептов (recipe-book-tma)

Telegram Mini App: один файл `index.html`, без сборки. Тесты на `node:test`.

## Запуск и тесты
- Тесты: `npm test` (сейчас 41/41 должны проходить).
- Локальный просмотр: `python3 -m http.server 8765 --bind 127.0.0.1`, открыть `http://127.0.0.1:8765/index.html`.

## Структура
- `index.html` — всё приложение. Модульный скрипт (Firebase 10.14.1 из gstatic) и обычный `<script>` с логикой. Тесты заходят в обычный `<script>` через `vm`, поэтому в нём не должно быть `firebase`.
- `tests/check.test.js` — логика рецептов, категории, сиды.
- `tests/firebase.test.js` — статические проверки подключения Firebase.
- Firebase: проект `katya-recipes`, веб-приложение `recipe-book-web`.

## Бот
- Telegram-бот: `@recipe4katyabot`.
- Описание в BotFather задаётся командой `/setdescription` (лимит 512 символов), «о боте» — `/setabouttext` (лимит 120). Текст брать из утверждённого источника, не из памяти.
- Токен бота и ключ Claude API — только в серверных секретах, никогда в репозитории и в чате.

## Планируемая функция: рецепт по ссылке или скриншоту
- Источники: Telegram, Facebook, Instagram, TikTok, YouTube, скриншот.
- Поток: бот или Mini App принимает вход → serverless-функция вызывает LLM с поддержкой изображений → черновик показывается пользователю → после одобрения сохраняется в Firestore.
- Рецепты привязаны к Telegram user id из `initData`, синхронизируются по аккаунту.
- Языки интерфейса: иврит, русский, английский, арабский.
- Модель для старта: Haiku 5.5 (`claude-haiku-5-5`), Sonnet 5.5 — если качество на иврите/арабском хуже.
- Черновик всегда сначала на одобрение пользователя.

## Правила работы
- Сначала описание решения и вопросы, потом код.
- После изменения логики — тесты, и только если они проходят, двигаться дальше.
- Не восстанавливать тексты и файлы по памяти: брать из исходника (например, из файла инструмента).
- Описание BotFather сейчас говорит «данные хранятся на вашем устройстве»; при синхронизации по аккаунту его нужно обновить.
